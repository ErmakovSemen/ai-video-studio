# Пул доработок → передача заказчику

Аудит от 2026-07-22. Что реально мешает отдать сайт клиенту, по приоритету.

## Ключевое решение по архитектуре

**Одна установка = один воркспейс клиента.** Полноценная мультиарендность (изоляция
данных между многими компаниями в одной инсталляции) — это недели работы: user_id в
сессии, пер-юзерные проекты/доски/выхлопы/токены соцсетей. Для передачи ОДНОМУ
заказчику это не нужно: он получает свою инсталляцию, свои соцсети, свой контент.
Зарегистрированные пользователи = его команда, работают в общем воркспейсе.

Это сокращает путь с «недели» до «дня-двух». Если позже понадобится продавать
многим клиентам с одной инсталляции — это отдельный большой этап (см. Backlog).

## P0 — блокеры (без этого отдавать нельзя)

- [x] **Онбординг воркспейса.** Сейчас всё захардкожено на проект «Чайный»
      (`FACTORY_PROJECT=chayniy`, в навигации `?name=chayniy_content`). Клиент
      входит и видит чужой чайный канал. Нужен мастер первого входа: название,
      тема, стиль, голос → создаётся ЕГО проект, вся навигация переключается на него.
- [x] **Библиотека «Мои видео».** Сгенерировал ролик → ушёл со страницы → он потерян.
      Нет ни одного места, где видно все созданные видео. Нужен экран со всеми
      роликами: превью, скачать, опубликовать, удалить.
- [x] **Единый дизайн.** 6 страниц ещё на старом стиле: `board`, `clip`, `connect`,
      `index`, `montage`, `terms/privacy`. Клиент кликает «Контент» из меню и
      попадает в визуально другой продукт.
- [x] **Мёртвая «Студия».** `/studio` (сырой JSON-редактор сценариев, список готовых
      сценариев) больше не в меню, но роут открыт. Это инструмент разработчика —
      убрать из продукта.

## P1 — сырость, видно сразу

- [ ] **Онбординг подключений.** Мастер «подключи YouTube/Telegram» вместо страницы

## 1. Что это за продукт

**Прометей** — ai-first видеоредактор нового типа. Не «монтажка с ИИ-функциями»,
а конвейер, который делает ролик от идеи до публикации и умеет ставить выпуск
контента на поток.

- Репозиторий: `ErmakovSemen/ai-video-studio` (GitHub, ветка `master`)
- Прод: **https://72-56-95-104.sslip.io**
- Владелец: Семён Ермаков (simonermakoveng@gmail.com)

**Позиционирование (формулировка владельца, дословно):** «Мы ai-first продукт,
конкурируем с kaze и обычными приложениями для монтажа. Наше преимущество, что
мы можем e2e создавать видео и поставить выход видео на поток. Должна быть
возможность работать над шортсом, исправляя генерацию путём текста и картинок».

**Аудитория:** малый бизнес, энтузиасты, маркетинговые отделы.

**Три сценария использования, которые продукт закрывает:**
1. Ролик с нуля из текстовой идеи (сценарий → кадры → озвучка → монтаж → публикация)
2. Нейромонтаж загруженного видео
3. Нарезка длинного видео на вертикальные Shorts с субтитрами

## 2. Как это устроено технически

### Стек

Осознанно минималистичный, без сборки фронтенда:

- **Бэкенд:** FastAPI, один процесс, `app/main.py` (~1500 строк)
- **Фронтенд:** ванильные HTML/CSS/JS. Никаких React/Vue/npm. Дизайн-система в
  одном файле `app/static/ds.css`
- **Кабинет:** оболочка с iframe — боковая навигация грузит страницы внутрь
- **Фоновые задачи:** словарь `JOBS: dict` + `threading.Thread`, фронт опрашивает
  `/api/jobs/{jid}`. Никаких Celery/Redis
- **Тяжёлые задачи:** семафор `HEAVY_JOB_LOCK` — на 1 ГБ памяти два рендера
  одновременно убивают контейнер
- **Хранение:** JSON-файлы в `config/` (gitignored). Базы данных нет вообще
- **Доска контент-плана:** JSON в GitHub через Contents API (`studio/boardsync.py`)

Всего Python-кода ~6500 строк в `app/`, `studio/`, `publish/`.

## 4. Автономная фабрика агентов

Пять агентов, каждый отвечает за свой столбец доски. Оркестратор
`studio/factory/run.py`, запускается systemd-таймером **каждые 15 минут**,
один тик = один шаг конвейера.

Порядок приоритета внутри тика:

1. `director` — публикует одобренное (дёшево по CPU, дорого по последствиям)
2. `reviewer` — ревьюит отрендеренное, может вернуть на переделку
3. `producer` — рендерит следующую идею (самый тяжёлый шаг)
4. `creator` — пополняет очередь идей
5. `analyst` — раз в сутки считает аналитику

Всё под `flock`, чтобы тики не наложились. Автономный режим включается флагом,
таймер сам себя гасит, если флаг снят.

Ревьюер работает по-настоящему: в истории есть возвраты на переделку с
внятной претензией («Хук не совпадает с первой сценой озвучки… зритель ждёт
ответа на первый вопрос»).

**За всё время фабрика опубликовала 26 роликов.**

## 5. Язык камеры (`studio/motion.py`) — свежая фича

Сделано 11.08. Раньше сцена несла поле `motion` — свободную строку от LLM («slow
pan»). Строка уходила в две несовместимые точки: image-to-video модель трактовала
её как придётся, а бесплатный ffmpeg-черновик игнорировал вовсе и крутил один и
тот же зум на каждой сцене. Ролики выходили вялыми и однообразными.

Теперь есть словарь из **девяти приёмов**, каждый — согласованная четвёрка:

- `prompt` — формулировка на языке, который модели понимают
- `ff` — ffmpeg-фильтр, дающий тот же приём **бесплатно**
- `genre` / `ramp` — параметры Higgsfield cinematic_studio
- `beat` — драматургический такт (hook / build / payoff)

Приёмы: `push_in`, `pull_back`, `crash_zoom`, `orbit`, `tilt_up`, `handheld`,
`whip_pan`, `static_hold`, `fpv_dive`.

Сценарист выбирает id из списка, а не сочиняет текст. Неизвестный id
подменяется приёмом, уместным для места сцены в ролике, — отсебятина модели
ничего не ломает. Фильтры считают движение через прогресс сцены 0..1, поэтому
приём укладывается ровно в её длительность.

**Главный эффект:** черновик и платная генерация дают одну раскадровку,
отличаясь только фотореализмом. Черновик перестал быть заглушкой.

Проверено: 27 комбинаций длительность×приём без ошибок ffmpeg; на живом
сценарии LLM вернула 5/5 валидных id без повторов подряд.

## 6. Деньги

### Модель монетизации

**Пакет (подписка с включённым объёмом) + оверадж сверх квоты.** Не «процент с
использования»: процент требует, чтобы у клиента были свои ключи к
ИИ-провайдерам, а это ровно то, чего продукт избегает.

Тарифы (`studio/billing.py`): Пробный (0₽, 3 ролика), Старт (990₽/мес, 15),
Поток (3900₽/мес, 60, автопилот, популярный), Студия (11900₽/мес, 250,
безлимитный монтаж).

Тариф влияет на модель генерации: `basic` → Gemini Flash, `quality`/`max` →
Claude Sonnet 4.5. То есть «повышенное качество» — реальное отличие, а не
маркетинг.

| Кадры (Gemini Flash Image, ~6 сцен × 2.5 попытки QC) | ~$0.048 |

### Кошелёк

`studio/wallet.py` + страница `/wallet`: баланс, журнал транзакций, промокоды,
заявки на пополнение. Прайс разовых операций: ролик 39₽, монтаж 59₽, нарезка 59₽.
Комиссия на пополнение 5%.

Квоты и деньги сведены в одни ворота (`_gate()` в `app/main.py`): сначала лимит
тарифа, при исчерпании — списание с баланса. `_settle()` фиксирует **по факту
готового результата**, поэтому за упавшую генерацию клиент не платит.

Промокод `ХОЗЯИН2026` (kind=no_fee, бессрочный) снимает комиссию — заведён,
чтобы владелец пополнял через сайт без наценки.

### ⚠️ Настоящего эквайринга НЕТ

Это надо понимать буквально: **деньги на счёт не приходят**. Система учётная, а
не касса. Кнопка «Я оплатил» — ручное подтверждение владельца.

Единственная точка интеграции — `wallet.confirm_topup()`. Туда встанет вебхук
провайдера, когда появится мерчант-аккаунт (ЮKassa / Тинькофф / Робокасса).

## 8. Текущие проблемы

### 🔴 КРИТИЧНО — фабрика заклинена намертво (обнаружено 11.08)

**Симптом:** с 06.08 фабрика в состоянии `idle`, каждые 15 минут пишет «в
очереди уже 2 идей, пропускаю». Пять дней ничего не производит.

**Причина найдена точно.** В `studio/factory/producer.py:47`:

```python
for c in ideas:
    if c.get("rendering_failed"):
        continue        # <- пропускается НАВСЕГДА, никто флаг не снимает
```

Обе идеи в очереди помечены `rendering_failed=True` (retries 2 и 1). Дальше
замыкается круг: `producer` их пропускает → очередь не пустеет → `creator` не
добавляет новые (`MIN_IDEAS = 2` в `creator.py:6`) → конвейер стоит вечно.

Счётчик `retries` инкрементируется, но **нигде не используется**. Флаг
`rendering_failed` не снимается никогда.

**Что чинить:** сбрасывать флаг по истечении паузы (экспоненциальный backoff),
после N попыток убирать карточку в «нужна помощь» и слать уведомление, а
`creator` считать в очереди только живые карточки.

### 🔴 КРИТИЧНО — отказы не видны

Предыстория, которая объясняет масштаб проблемы: **с 22.07 по 05.08 фабрика не
опубликовала ни одного ролика.** Протух YouTube-токен, `director` падал с
`invalid_grant` каждые 15 минут — ~94 раза в сутки, **1336 холостых коммитов**
«publish failed» в историю репозитория. Дашборд всё это время оставался зелёным,
и никто не знал две недели.

Токен обновлён 11.08, но причина не устранена: система по-прежнему **умеет
ломаться молча**. Именно это, а не недостающие функции, — блокер номер один
перед сдачей заказчику.

Нужно: строка «последняя успешная публикация N часов назад» на дашборде, красный

## 9. Ловушки, которые уже стоили времени

Каждая была неочевидна и отняла часы. Не наступать повторно:

1. **ffmpeg без `drawtext`.** Встроенный в `imageio_ffmpeg` бинарь собран без
   этого фильтра — субтитры молча не рисовались. Лечится `studio/ffbin.py`,
   который предпочитает системный ffmpeg и падает громко, а не тихо.
2. **`credentials.json` перебивает env.** `publish/config.py` берёт значение
   сначала из `config/credentials.json`, и только потом из переменной окружения.
   Обновление токена в `.env.prod` может не подействовать.
3. **Timeweb блокирует по IPv4.** Анти-фрод требует предоплату ~6000₽. Обходится
   тем, что OpenRouter доступен по IPv6, а воркеры поднимаются с `--network host`.
4. **Перенос текста в символах.** Кадр 720px шириной, а строка из 21 заглавной
   кириллической буквы при кегле 54 занимает 747px — текст обрезался. Лечится
   `compose._fit_text()`, который меряет реальным шрифтом.
5. **Диск 14 ГБ забивается** при частых пересборках. В деплой добавлена очистка
   build-кэша, `data/` и `*.mov` в `.dockerignore`.
6. **Память 1 ГБ.** Два тяжёлых рендера одновременно убивают контейнер, отсюда
   `HEAVY_JOB_LOCK`.
7. **opencv 5.0.0 не имеет `CascadeClassifier`** — закреплена версия 4.10.0.84.
8. **Кириллические слаги** схлопывались в пустоту — добавлена таблица транслитерации.

## 10. Архитектурные решения и почему так

- **Одна установка = один воркспейс.** `config/workspace.json` — глобальный файл.
  Все зарегистрированные аккаунты видят один и тот же воркспейс, кошелёк, квоту и
  подключённый YouTube-канал. Каждый клиент = отдельная инсталляция.
  **Следствие по безопасности:** открытая регистрация означала бы, что любой
  зарегистрировавшийся получает канал и кошелёк клиента. 11.08 регистрация
  закрыта кодом-приглашением `SIGNUP_CODE`.
- **Сценарий до рендера.** Раньше было: идея → 2 минуты вслепую → ролик. Стало:
  идея → сценарий на экране с правкой по сценам → рендер. Пользователь видит,
  за что платит, до того как потратит время.
- **Никакой БД и сборки фронтенда.** Продукт должен разворачиваться на самом
  дешёвом VPS одной командой.
- **Черновик бесплатный и честный.** ffmpeg-тракт даёт ту же раскадровку, что и
